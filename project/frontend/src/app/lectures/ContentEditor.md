# Техническое Задание: Блочный редактор контента "ContentEditor"

**1. Контекст и основная цель**

**Задача:** Разработать и интегрировать в проект блочный редактор `ContentEditor` для создания и управления контентом. Редактор должен обеспечивать интуитивный пользовательский опыт, схожий с Notion или Medium, и позволять авторам создавать контент из различных типов блоков (текст, формулы, код, изображения).

**Ключевое требование:** Редактор должен быть реализован с использованием фреймворка **Tiptap v2**, чтобы абстрагироваться от низкоуровневой логики `content-editable` и обеспечить расширяемую и поддерживаемую архитектуру.

**2. Технологический стек**

*   **Фреймворк редактора:** **Tiptap v2**
*   **Фреймворк приложения:** React, Next.js
*   **Стилизация:** SCSS Modules / Tailwind CSS (уточнить по проекту)
*   **Редактор кода:** Monaco Editor (`@codesandbox/sandpack-react`)
*   **Рендеринг формул:** KaTeX (`react-katex`)
*   **Drag-and-Drop:** Встроенные возможности Tiptap; `dnd-kit` при необходимости.
*   **Обработка форм (если применимо):** React Hook Form

**3. Требования к хранению данных**

Контент **не должен** храниться как единая Markdown или HTML строка. Tiptap предоставляет возможность экспортировать контент в формате JSON. Этот JSON-объект должен быть основной формой хранения контента в базе данных.

**3.1. API**
Бэкенд предоставляет следующие эндпоинты (разработка API не входит в данную задачу, но исполнитель должен с ними взаимодействовать):
*   `GET /api/content/[id]`: Получение данных сущности, включая поле `content` в формате Tiptap JSON.
*   `PUT /api/content/[id]`: Обновление сущности. Принимает полный объект с обновленным полем `content` в формате Tiptap JSON.
*   `POST /api/upload/image`: Загрузка изображения. Принимает `FormData`, возвращает `{ "url": "..." }`.

**4. Требования к функциональности редактора**

Редактор должен быть реализован как единый React-компонент `ContentEditor`, который принимает `initialContent` (Tiptap JSON) и колбэк `onSave(content)`.

**4.1. Кастомные блоки (Custom Nodes)**

Необходимо реализовать следующие кастомные блоки как Tiptap-расширения:

**A. Блок "Текст" (`Paragraph`, `Heading`)**
*   Используются стандартные расширения Tiptap.
*   Должна быть реализована базовая стилизация (жирный, курсив, зачеркнутый).

**B. Блок "Формула" (`FormulaNode`)**
*   **Хранение:** Нода должна хранить LaTeX-строку в своих атрибутах (`attrs: { latex: '...' }`).
*   **Рендеринг:** Для отображения ноды должен использоваться `NodeView` с кастомным React-компонентом. Этот компонент должен:
    *   В режиме просмотра рендерить формулу с помощью `react-katex`.
    *   При клике переходить в режим редактирования, отображая текстовое поле (`<input>` или `<textarea>`) для изменения LaTeX-строки.
    *   При `onBlur` (потере фокуса) сохранять изменения и возвращаться в режим просмотра.

**C. Блок "Код" (`CodeBlockNode`)**
*   **Хранение:** Нода должна хранить код и язык программирования в атрибутах (`attrs: { language: 'jsx', code: '...' }`).
*   **Рендеринг:** Использовать `NodeView` с кастомным React-компонентом, который инкапсулирует `@codesandbox/sandpack-react`.
    *   Компонент должен быть загружен асинхронно (с помощью `next/dynamic`).
    *   Должен присутствовать UI для выбора языка программирования из предопределенного списка (`javascript`, `typescript`, `python`, `go`, etc.).

**D. Блок "Изображение" (`ImageNode`)**
*   Использовать стандартное расширение Tiptap `Image`.
*   Расширить функциональность для поддержки загрузки файлов:
    *   При перетаскивании файла изображения в редактор, он должен быть загружен на сервер через эндпоинт `POST /api/upload/image`.
    *   Во время загрузки должен отображаться плейсхолдер с индикатором прогресса.
    *   После успешной загрузки плейсхолдер должен быть заменен на `ImageNode` с URL, полученным от API.

**4.2. Пользовательский интерфейс и взаимодействие**

**A. Плавающее меню (`BubbleMenu`)**
*   Должно появляться при выделении текста.
*   Должно содержать кнопки для базового форматирования: Bold, Italic, Link.

**B. Слеш-команды (`Slash Commands`)**
*   При вводе `/` в начале новой строки должно появляться меню для быстрой вставки блоков.
*   Меню должно позволять вставить: Заголовок, Текст, Формулу, Блок кода, Изображение.
*   Для реализации использовать расширение Tiptap `Suggestion`.

**C. Перетаскивание блоков (Drag-and-Drop)**
*   Пользователь должен иметь возможность менять блоки местами, перетаскивая их за специальный "хэндл" (handle), который появляется при наведении на блок.
*   Необходимо использовать встроенные возможности Tiptap для D&D.

**5. Нефункциональные требования**

*   **Производительность:** Редактор должен оставаться отзывчивым при работе с длинными документами (100+ блоков).
*   **Надежность:** Реализовать механизм автосохранения (например, в `localStorage` каждые 5 секунд). При повторном открытии редактора предложить пользователю восстановить несохраненные изменения.
*   **Чистота кода:** Код должен быть разделен на логические модули. Каждое расширение Tiptap, NodeView и связанные с ними UI-компоненты должны находиться в своей директории.
*   **Документация:** Ключевые и неочевидные моменты в коде должны быть прокомментированы.

**6. Критерии приемки**

1.  Редактор успешно инициализируется с данными, полученными от API.
2.  Все кастомные блоки (`текст`, `формула`, `код`, `изображение`) создаются, редактируются и отображаются корректно.
3.  Функциональность меню (`BubbleMenu`, `Slash Commands`) работает без ошибок.
4.  Drag-and-Drop блоков работает плавно и предсказуемо.
5.  Загрузка изображений реализована и отображает состояние загрузки.
6.  При сохранении контент отправляется на API в корректном Tiptap JSON формате.
7.  Механизм автосохранения и восстановления реализован и протестирован.
8.  Компоненты Monaco Editor загружаются асинхронно.
9.  Код соответствует стандартам проекта (ESLint, Prettier) и имеет логичную структуру.
